# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

DeepSkyStacker (DSS) is a C++23 / Qt 6.10 astrophotography stacking application for Windows, Linux and macOS (BSD 3-Clause). Version is set in `CMakeLists.txt` (`project(... VERSION ...)`), `CurrentVersion.txt`, and `DeepSkyStackerKernel/DSSVersion.h`; release installers live under `Installers/{Windows,Linux,macOS}`.

## Build

- **Windows (primary dev environment):** open `DeepSkyStacker.VS2022.sln` in Visual Studio 2026 (do *not* accept the retarget/upgrade prompt on older solutions). Requires Qt 6.10.0 with the Qt VS Tools named installation `6.10.0_msvc2022_64`, vcpkg (triplet `x64-windows-static-md`), and Visual Leak Detector 2.5.12 installed at `C:\Program Files (x86)\Visual Leak Detector`. Shared settings are in `Debug.props`, `Release.props`, `vcpkg.props`.
- **Linux/macOS:** CMake + Ninja via `CMakePresets.json` (e.g. `DSS-Debug-Linux`, `DSS-Release-Linux`; Qt path comes from the `QTDIR` env var, vcpkg from `VCPKG_ROOT`). Build output goes to `build/`. See `Setup Linux.txt` / `Setup MacOS.txt`.
- Dependencies are declared in `vcpkg.json` (cfitsio, exiv2, libraw, tiff, brotli, boost, smtpmime, …) with pinned versions/overlays in `vcpkg_overlay_ports/`.
- Each project is dual-maintained: a `.vcxproj` (+ `.filters`) **and** a `CMakeLists.txt`. When adding/removing a source file, update both.

## Tests

Tests are in `DeepSkyStackerTest` using the bundled Catch2 amalgamated header (`catch_amalgamated.hpp`); each test file registers its own `TEST_CASE`s and `DeepSkyStackerTest.cpp` is just the entry stub. Build the `DeepSkyStackerTest` project, then run the executable; Catch2 CLI filters work for a single test, e.g. `DeepSkyStackerTest.exe "test name"` or `DeepSkyStackerTest.exe "[tag]"`. New test files must be added to the test project's source lists (vcxproj and CMake). Warnings are treated as errors in the test project.

## Architecture

Solution projects:

- **DeepSkyStackerKernel** – the core library with no GUI dependence: bitmap/image types (`BitmapBase`, `ColorBitmap`, `MemoryBitmap`…), file format I/O (FITS via `FITSUtil`, RAW via libraw, TIFF, exiv2 metadata), star registration/alignment (`ChannelAlign`, `Delaunay`-based matching), calibration (`DarkFrame`, `FlatFrame`, `BackgroundCalibration`), stacking engine (`DeepStack`, `ColorMultiBitmap`, AVX-optimised accumulate/histogram/entropy code), cosmetic/debloom filters, and progress reporting through `DSSProgress`. Both front-ends link this.
- **DeepSkyStacker** – the Qt GUI application (dialogs, explorer bar, stacking/batch/comet dialogs, image view, `.ui` forms and generated files in `GeneratedFiles`).
- **DeepSkyStackerCL** – console front-end (`progressconsole.*` implements the progress interface for the CLI).
- **DeepSkyStackerLive** – live-stacking application that monitors a folder and stacks incoming frames.
- **DeepSkyStackerTest** – Catch2 tests; **PerformanceTests1** – benchmarks.
- `Tools/` (shared Qt widgets), `ZClass/` (legacy tracing/pointer utilities), `qwt/` (charting, vendored), `Help/` (CHM help).

Each project has an `i18n/` directory of Qt `.ts` translation files (ca, cs, de, en, en_GB, es, fr, it, ja_JP, nl, pt_BR, ro, ru, tr, zh_CN, zh_TW). User-visible strings use Qt's `tr()`; the `.ts` files get regenerated by `lupdate`, so large noisy diffs in them are expected after string changes.

## Coding conventions (from `Coding Guidelines.md`)

- C++ casts only (no C casts); `qobject_cast` for QObjects, never `dynamic_cast`.
- camelCase names; **no Hungarian notation**; members use a trailing underscore (`image_`) (or `m_name` at worst); classes have no `C` prefix (`DeepStack`, not `CDeepStack`); accessors are `description()`/`setDescription()`, not `getDescription()`.
- Prefer `enum class` and `constexpr`/`constinit` over `#define` and plain enums; `using` over `typedef`.
- Allman braces (opening brace on its own line); omit braces for single-statement bodies; one blank line max; comment lines under ~80 columns.
- Overrides use `override` without repeating `virtual`.
- Comment the *why* and *how*, especially for non-obvious algorithms; "clever" code requires explanatory comments.
